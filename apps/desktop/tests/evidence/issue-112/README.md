# Issue #112 · Windows 富文本验收

两轮分别启动独立的 Windows Tauri 客户端、测试资料目录和本机在线服务。聊天样本及账号均为测试数据。WebView2 截图视口为 1024 × 751，DPR 为 1。

## 第一轮 Always UI check

| 级别 | 位置 | 观察和影响 | 修正 |
| --- | --- | --- | --- |
| 缺陷 | 图片悬停弹层 | 方图底部被裁掉，用户看不到完整图片 | 按原始比例和视口剩余空间缩放弹层 |
| 高置信度设计问题 | 气泡引用和任务列表 | 引用继承浏览器大缩进，任务勾选过淡 | 使用紧凑的引用间距和有辨识度的只读勾选 |

实际双端收发和复制通过。预览加载公网 PNG，回环目的地安全降级。该轮在重启后的 WebView2 调试连接口遇到连接重置，后续验收使用新端口。

## 第二轮 Always UI check

- 浅灰色语法高亮、四种公式分隔符、只读任务列表和长引用摘要均可读。已实测移除长引用、复制代码、复制原文、按原文搜索及本机服务共享的合成 AI 回复。
- 普通与私密聊天均在 500 ms 悬停后直接预览。公网 PNG 完整显示；同一真实 WebView2 的横竖比例测试使用本机生成的 PNG。原图尺寸及显示尺寸分别为方图 480 × 480 → 238 × 238、横图 600 × 150 → 302 × 75.5、竖图 120 × 480 → 59.5 × 238。
- 一条宽内容消息的正文容器为 493 px，代码、表格和块公式的滚动宽度分别为 3116、1322 和 3351 px。时间线无横向溢出，图片预览开合前后气泡位置和尺寸一致。一次会话切换往返约 70 ms，含自动化操作耗时。
- 真实同机双客户端完成加密 LAN 私密会话和富文本往返。结束后对端的预览消失，两个应用资料的 SQLite 和测试服务 PostgreSQL 中均无该私密原文。
- WebView2 在消息显示及原生图片预览期间观测到零相关 HTTPS 请求。回环地址通过键盘触发后显示精简的失败状态。模拟服务断线后待发消息恢复送达，重启客户端后正文原文与渲染一致。

## 验证范围

iPhone／iPad 真机、物理双机 LAN、真实 AI 提供商、系统浏览器落地页及公网条件下的重定向到内网、超限、超时和 DNS 变化未完成端到端实测。原生策略单测覆盖地址拒绝、MIME 与实际内容不符、SVG 拒绝及取消请求的两种 IPC 顺序。
