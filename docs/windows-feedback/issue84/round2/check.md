# 第 2 轮 Always UI check

关闭首轮进程，再启动内置资源版 Windows Tauri 客户端，使用同一份合成会话重新输入、操作并截图。系统显示缩放为 175%。实测视口为常规窗口 1191 × 791、最大化 1463 × 867、独立启动的窄窗 535 × 711 CSS px。

| 检查项 | 本轮观察与影响 | 实测 |
| --- | --- | --- |
| C01/C03/C05/C06/C23 · 输入层级 | 空输入时三个控件居中，约 47 px 的胶囊承载一层描边和常态投影。发送是本区唯一高强调操作。聚焦变色且尺寸一致 | [空输入](wide-idle.png) · [聚焦](wide-focus.png) |
| C06/C08 · 操作位置 | 单行时两侧按钮垂直居中。文字向上扩展时，两按钮保持单行时的横纵坐标 | 重启客户端后在 1191 CSS px 宽窗复测 1、2、5、6、7 行和内部滚动，两个按钮的坐标一致。在 535 CSS px 实际窄窗中，从一行到填入长草稿并滚到底，两个按钮也保持原位。[窄窗单行](narrow-idle.png) · [窄窗长稿](narrow-534.png) |
| C16/C17 · 长内容与滚动 | 1、2、5、6、7 行的编辑区高度为 36、56、116、136、136 CSS px。记录区跟随让位。窄窗长草稿 1376 px 内容高在 136 px 编辑区内纵向滚动，横向滚动宽度与可见宽度相同 | [窄窗](narrow-idle.png) · [窄窗长草稿](narrow-534.png) · [最大化](maximized.png)。恢复窗口后回到原尺寸，窄窗菜单全部位于视口内 |
| C11/C19 · 渐隐与编辑 | 剪裁状态按实际滚动位置切换。到底后仍可读完整可见行、光标清晰，顶部能看到淡出 | [未溢出](fade-none.png) · [顶端](fade-top.png) · [中间](fade-middle.png) · [底部](fade-bottom.png) |
| C11/C13/C19 · 原生输入 | Tab 到编辑器，Shift+Enter 换行，Enter 发送，切换会话可取回草稿。超限提示明确并禁用发送，输入 `@` 后出现建议。Windows 系统拼音输入 `ni` 后出现候选，空格提交「你」到草稿 | [系统拼音候选](native-ime.jpg) · [首次验收的 WebView2 组合输入](composing.png) |
| C09/C11/C20 · 附件与粘贴 | 两个菜单项分别打开 Windows 文件和文件夹选择器，选择后会话收到 TXT 和 ZIP 文件卡片。从资源管理器复制合成文件，编辑区 Ctrl+V 先显示目标会话和文件名，确认后发送。纯文本和图片分别通过 Ctrl+V 与右键粘贴，图片也成功发送 | [两项加号菜单](tools.png) · [资源管理器粘贴确认](explorer-confirm.png) · [发送结果](attachments-sent.png) · [右键图片](image-context.png) · [快捷键图片](image-keyboard.png) |

本轮未发现需要继续调整的输入器问题。iPhone 和 iPad 的实机验收为 **BLOCKED**，当前环境没有对应设备。
