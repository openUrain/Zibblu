# Zibblu Design System · 跨平台 UI / UX 视觉准则

> **批准来源**：Owner 2026-11-17 的 [Issue #54](https://github.com/openUrain/Zibblu/issues/54) 和 2026-11-14 的既有决定。
>
> **状态**：目标设计规范。交互以 Owner 的真实平台验收为准。
>
> **适用范围**：桌面（Windows/macOS）、手机（Android/iOS）、平板（iPad/Android）及后续新增页面。  
> **权威边界**：视觉规则不覆盖 `docs/SECURITY.md` 的安全限制、不改变 M1/M2/M3 协议与授权模型。

## 1. 核心定位与参考范围

**唯一的 UI/UX 对照基线是各端微信**。Windows 对照 Windows 微信，iPhone 对照 iOS 微信，iPad 对照 iPad 微信。常规聊天、群组、联系人、个人资料、设置、导航、保存状态与手势逐项对照。继续使用 Zibblu 原创品牌标识、图标和 Lavender 配色。

## 2. 规范等级、冲突处理与迁移

- **MUST**：Owner 确认的不可随意偏离的目标；新增 UI 和重构要遵守。
- **SHOULD**：强烈建议的默认实现；因平台约定、可访问性、屏幕限制而偏离时要在 PR 写明。
- **MAY**：按产品实际情况适度发挥。
- 优先级：安全和隐私真实性 > 关键操作可达性/无障碍 > 核心信息架构和交互一致性 > 视觉效果。
- **当前代码不一致 ≠ 自动修改权限**。以本规范记录差距，在单独授权的 UI 实施 PR 逐步调整。不得借“统一视觉”大改服务协议、私聊安全或 AI 权限。
- 所有平台共享**设计语言、语义 Token、图标含义和操作心智模型**，但不是逐像素复刻；桌面、手机、平板遵循各自的输入方式与导航惯例。

## 3. 颜色、字体、图标、材质

### 品牌颜色和主题

- **MUST**：主品牌色为**薰衣草色 Lavender**。普通应用与普通聊天采用**带极轻薰衣草倾向的浅色底色**，高可读内容面板保持明净。
- **MUST**：**私密聊天保持独立深色主题**。当前私聊深色主题先保留，不因全局浅色设计把私聊改为浅色。普通界面本期不新增全局暗色切换要求。
- **MUST**：建立统一的颜色语义 Token，例如 `brand.lavender`、`action.primary`、`surface.canvas`、`surface.panel`、`text.primary`、`text.muted`、`border.subtle`、`private.surface`、`status.error`。不要在页面里自行创造互不兼容的紫色。
- **MUST**：文字、图标、焦点、高亮、危险状态需满足实际平台可访问性；至少按 WCAG AA 检查主要文本和交互对比度。**安全/连接状态不能只靠颜色表示。**
- **精确 HEX 尚未由 Owner 确认**。以下为初次原型候选，**不是已冻结品牌色值**：Lavender `#A78BFA`、高对比操作紫 `#6B46B1`、浅画布 `#F8F6FC`、内容面板 `#FFFFFF`、主文字 `#242033`。正式定值前应提供对照截图和对比度检查。现有 CSS 色值不等于 Owner 最终批准。

### 字体、图标、层次

- **MUST**：正文使用各端**原生系统字体**，尊重系统字体缩放及中英文排版；不强迫全端统一下载同一第三方字体。
- **MUST**：图标默认**线性风格**，已选中项可切换为对应的**实心形态**；相同功能不能在不同页面使用含义冲突的图形。激活状态不应只凭颜色表达。
- **MUST**：以小圆角和清晰分组为主，少用阴影和大圆角。消息气泡和消息反馈按各端微信的使用方式评估。
- **MUST**：以扁平表面为主；玻璃/模糊**只可适度用于弹窗、浮层、菜单**，需要无模糊回退。禁止全局铺满半透明卡片、渐变、发光和多重阴影。
- **MUST**：采用**微信式平衡信息密度**：可快速扫描，不拥挤也不过分留白；大/小屏都要保持内容层级。
- **SHOULD**：动效自然、流畅，有**适量弹性**，但不持续漂浮、反复弹跳、夸张飞入。常规转场可从 140–240ms 原型起步，最终数值由实际视觉验收确定；尊重减少动态效果设置，不以动画延误发送、输入、切换。

## 4. 跨端导航与布局

| 终端 | MUST 目标结构 | 原生适配 |
| --- | --- | --- |
| 桌面 | **三栏**：主导航 / 会话列表 / 当前内容（微信式） | 鼠标、键盘、右键、快捷键；窗口缩小时合理折叠，避免横向滚动 |
| 手机 | **四个底部入口**：聊天 / 联系人 / 文件 / 我的 | 长按消息、单手触控、层级返回、系统安全区域 |
| 平板 | **双栏**：列表 + 内容 | 支持横竖屏、分屏与浮窗宽度；不简单放大手机 UI |

- **MUST**：Token、信息层级、功能名称及能力边界跨端统一。
- **MUST**：各端允许导航形式和手势因平台而异，不能因“风格统一”牺牲原生可用性。
- **桌面**：主功能栏直达聊天、联系人、文件。左上显示登录用户头像并打开个人资料，左下菜单收纳设置、关于、反馈和退出登录。主功能栏标识当前页，列表当前项用薰衣草底色标识，保留键盘焦点和无障碍选择状态。
- **Windows 登录页**：用一张可聚焦的账号卡显示上次登录的头像、用户名和服务器。点击或按 Enter 后向服务器验证会话。并列提供使用其他账号的入口，失效时直接回到密码登录。
- **MUST**：手机文件入口仍遵守第 6 节“仅不能在聊天内直接预览、需下载的附件”的内容边界。

## 5. 聊天

- **MUST**：聊天列表采用**微信式头像—名称—最近消息预览—时间—未读标记**的紧凑清晰排布；不要给每条聊天加独立大卡片。
- **MUST**：输入区按各端微信的布局和触控尺度呈现输入、附件、发送。停靠软键盘出现时，由平台提供遮挡区域，仅避让输入区和同页滚动内容。
- **MUST**：消息操作以**微信式上下文菜单**为主：桌面右键、移动长按；功能仅显示真实支持且有权限的动作。
- **MUST**：群聊标题显示当前成员数。会话顶栏的「…」打开会话资料。单聊可进入对方资料，群聊展示当前成员和可用操作，两者都能查找当前会话的消息、文件、图片与视频。
- **MUST**：消息反馈**极简**，只突出必要的失败、未读、重试和连接状态。单聊双方开启回执时，当前会话最后一条为自己发出的消息才可显示勾选。单勾表示接收端已保存，双勾表示对方已查看。图标提供可访问名称，群聊和历史消息不显示勾选。
- **MUST**：已实现的消息历史、离线同步、撤回、引用、可见性、访问权限保持原语义；不要通过外观变更声称新增未实现的送达能力。

## 6. 文件与媒体

### 6.1 互斥的内容组织

- **MUST**：主导航的 **Files / 文件页** **只展示无法在聊天中直接预览、需要下载后查看或使用的普通附件**，如不可直接预览的文档、压缩包、安装包和其他格式。
- **MUST**：**图片、视频不混入文件页**；它们应当在各自会话的聊天记录/“查找聊天内容”里检索，聊天消息中在格式允许时直接预览。
- **MUST**：文件页、会话内文件筛选与媒体历史使用一致的分类原则，不能因后端统一返回附件就重新混合。不同平台无法预览某格式时要提供清晰的下载退路。
- **注意**：现有 Windows 文件中心可能仍展示媒体与全局传输数据，这是待迁移的**实现差距**，不代表本决策已经实现。

### 6.2 文件卡片、传输与管理

- **MUST**：聊天里的普通附件采用**微信式文件卡片**，以类型、名称、大小、必要操作状态为中心，视觉简洁。
- **MUST**：**传输进度直接在对应聊天文件卡片里显示**，微信式交互；暂停/继续/失败/重试等按真实能力呈现。不要把独立全局传输中心作为主要操作入口。
- **MUST**：文件可按类型、时间和名称查找。桌面用上下文菜单，触屏用长按或可见操作。保存、已保存、保存中和重试随真实状态显示。
- **MUST**：图片视频使用内置查看器，按现有能力提供缩放、前后切换、保存和分享。文件和图片的选择及导出用平台入口。
- **MUST**：继续遵循服务器访问授权、分块、断点续传、完整性校验；媒体分类或进度位置的改变**不授权修改文件安全语义**。

## 7. 个人主页、设置、私聊和 AI

- **个人主页 MUST**：从「我的」或桌面头像进入个人资料，再进入头像、名称、封面或简介的编辑页。保存、取消与返回回到资料页。选图后先预览，提供裁剪和缩放，用户确认后才提交。已有资料和图片优先读取按账号和服务隔离的本机缓存，连接服务后更新。
- **设置 MUST**：桌面分栏设置，手机微信式逐级列表，平板自适应；同一设置项的名称、作用与危险提示保持一致。
- **私聊 MUST**：**保留独立深色风格**，与普通聊天共享控件设计但明显区分状态。身份、LAN-only、认证和失败等必须有**文字与图标状态**，不能仅以“深色=安全”作隐私承诺。M2 仍需双方同意、认证加密局域网直连、无公网回退、不持久化、无云 AI。
- **AI MUST**：**视觉存在感尽量低**，仅在 `@自定义名称`、本次授权与必要回复标记时出现；不新增独立 AI 常驻面板或主导航。授权时仍必须清楚展示被外发的消息与文件范围、目标服务与确认，不因为极简而隐藏风险。

## 8. 信息表达、控件选择与视觉层级（Owner 新增四项硬约束）

### 8.1 用界面表达，少用说明文字

- **MUST**：优先通过布局分组、标题、图标、状态、留白、控件外观和合理操作顺序，让用户不读说明也能理解页面。**不要在每个模块下叠加一段“这里可以……”的解释**，也不要为显而易见的操作添加重复提示。
- **MUST**：默认只展示完成当前任务必要的信息。可推断的辅助解释、帮助教程、长段落、冗余提示语应删除或移到按需打开的帮助入口；空状态要简短并直接给出可执行的下一步。
- **例外不可删**：错误原因和恢复方式、危险/不可逆操作、权限与隐私边界、M2 LAN-only 身份与连接状态、M3 AI 外发内容与授权范围、必要的无障碍名称/提示，都必须明确表达。**少文字不等于隐藏风险或依赖猜测。**
- **评审问题**：删掉说明段落后，用户是否仍能从布局和控件看懂要做什么？若不能，应先改信息结构而不是补更多说明。

### 8.2 控件要符合数据类型与操作逻辑

- **MUST**：先确定任务、状态模型和期望反馈，再选控件；不能为了视觉趣味而滥用滑块、开关、复选框或弹窗。
- **选择规则**：
  - **滑块 Slider**：用于有明确上下限、可连续或分档调整且适合直接比较大小的数值（如音量、缩放、合理的强度设置）；给出可见范围/当前值，支持键盘与无障碍操作。若需要精确输入，提供数字输入或明确的刻度，不用滑块替代精确数值。
  - **复选框 Checkbox**：用于独立的多选项或批量选择；单选互斥项用单选按钮/分段控件，不要用多个复选框假装单选。
  - **开关 Switch**：用于明确的**即时二元设置**（开/关），状态应与真实设置同步；可能影响隐私、安全或费用的开关须清晰说明后果。
  - **单选/分段控件 Radio/Segmented**：少量互斥选择；选项很多时用选择器或搜索列表，而不是堆满按钮。
  - **按钮 Button**：用于执行动作（发送、保存、确认、删除），不应伪装成持久设置状态。
- **MUST**：选择控件后保持清晰的选中、禁用、加载、失败和保存反馈，并尊重桌面键鼠、移动触控及无障碍。**能直接操作就不额外增加确认步骤**；破坏性、安全与外发授权例外。
- **MUST**：滑块等控件是“合适时善用”，不是每个页面都必须出现，也不是一律缩减控件数量。

### 8.3 一种状态，一套足够的视觉信号

- **MUST**：禁止**重复套框和重复选择符号**。例如“可选卡片描边 + 内层选框 + 单独勾选图标”同时表达同一选择时，默认只保留一种明确的主选中标记，必要时用轻微背景/文字辅助。
- **MUST**：一个完整可点击的列表项/卡片应当有清楚的一致点击区域；不要出现框套框、按钮套按钮、连续分隔边框或同一层级反复描边。复选框只在需要明确多选语义时出现，且不能牺牲键盘和屏幕阅读器的选中反馈。
- **MUST**：尽量通过布局、留白、对齐、选中底色和轻分隔线组织元素。浮层、卡片和内层控制仅在承担**不同操作职责**时允许嵌套。
- **评审问题**：移除一个框、一层阴影或一个选中标记，操作状态是否仍完全清晰？如果是，删掉冗余层。

### 8.4 按重要性设计不同层级

- **MUST**：每个页面先确定**主任务、次级任务、辅助信息与危险操作**，并在尺寸、位置、留白、字重、对比度和交互突出程度上形成有秩序的层级。
- **主操作 Primary**：当前上下文最关键的明确动作才使用高强调设计；通常一个局部操作区域只应有一个同级主按钮。
- **次级操作 Secondary**：必要但不抢注意力，使用中性按钮或低强调样式；**三级/辅助操作 Tertiary** 使用文本按钮、图标、菜单等，优先按需出现。
- **破坏性动作 Destructive**：与普通主操作明确区分，按实际风险安排确认与错误恢复，不为追求“视觉统一”而隐去后果。
- **内容同样分级**：用户名/会话名/当前文件名优先于时间戳、辅助状态、技术细节；错误、安全与权限提示根据其真实重要性适当提升，而不是简单压低所有说明文字。
- **MUST**：高对比、高饱和 Lavender、粗体、大尺寸和动效均是有限的视觉注意力预算；不能多个相邻元素同时争夺“第一焦点”。不同模块允许有不同权重，但必须符合用户当前任务。
- **评审问题**：用户第一眼是否能看到最重要的内容和主操作？次级控件是否抢占注意力？危险与隐私信息是否被过度弱化？

## 9. 严禁的三大设计反模式（Owner 选择 30D）

1. **过度装饰**：多余玻璃、渐变、阴影、彩色装饰、过度动效或重复视觉强调。
2. **信息拥挤**：冗余入口、工具栏、标签、默认暴露过多高级功能、影响阅读的布局密度。
3. **交互割裂**：同一操作在不同页面语义/图标/反馈不同；跨端为图形一致而破坏各端习惯。

常规操作对照微信，颜色和素材使用 Zibblu 品牌资产。

## 10. Agent 实现流程与验收清单

Agent 在做 UI 工作前**必须**同时阅读本文件、`AGENTS.md`、`docs/PRODUCT.md`、`docs/SECURITY.md`。在 PR 中指出本次实现符合的条目、已知差距与平台实测情况。

- [ ] 视觉：Lavender 浅色、轻材质、小圆角、线性图标与原生字体；私聊深色不混用。
- [ ] 信息：页面主要靠布局和控件自解释，无冗长说明；危险、错误、LAN-only 和 AI 外发信息仍明确。
- [ ] 控件：滑块、复选框、开关、单选/分段控件与按钮与状态模型匹配，无装饰性滥用。
- [ ] 层级：主/次/辅助/危险动作和关键信息有清晰优先级；无框套框、重复勾选或多个抢主视觉的按钮。
- [ ] 聊天：微信式列表、群聊人数、输入区和菜单，桌面右键、触屏长按。
- [ ] 文件：文件页只列不可直接预览且需下载的普通附件。图片视频从聊天记录查找。文件卡片显示进度与真实操作状态。
- [ ] 主页/设置：首屏简洁；桌面分栏，手机逐级导航。
- [ ] 桌面三栏、手机四入口、平板双栏；键鼠/触控/分屏分别正确。
- [ ] 无安全状态伪装：M2 LAN-only、M3 单次可见范围、服务端普通消息传输语义不被视觉模糊。
- [ ] 动效克制且自然，支持减少动态效果；无过度装饰、信息拥挤、交互割裂。
- [ ] Windows 提供真实应用截图和权限操作证据。iPhone 提供真机录屏。iPad 提供真机或真实 iPadOS 环境证据。设备不可用标为 BLOCKED，由 Owner 确认交互验收。
- [ ] 保持文件媒体范围、私聊主题和 AI 逐次披露要求。
