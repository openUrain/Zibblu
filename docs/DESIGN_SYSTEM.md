# Zibblu Design System · 当前产品约束与 Always UI 工作规范

> **生效：2026-11-20。** 本文只保留 Zibblu 已确认的品牌、交互、功能与安全约束；**UI 设计方法、数值选择和审查规范以仓库内 [Always UI](../.agents/skills/always-ui/SKILL.md) 的固定版本及必读 references 为准**。
>
> 2026-11-14 的早期 30 项风格问卷、[Issue #54](https://github.com/openUrain/Zibblu/issues/54) 的旧版界面审计与截图属于**历史决策或测试证据**，不能直接覆盖 [Issue #59](https://github.com/openUrain/Zibblu/issues/59) 及后续 Owner 已批准的修改。旧选择中的 iMessage/Apple 风格措辞不再作为新增 UI 的默认设计指令。
>
> 设计流程由 Always UI 指导，但它**不覆盖** [安全边界](SECURITY.md)、[产品规格](PRODUCT.md)、实际平台行为、Owner 明确决策或已有用户数据契约。规范文字不等于代码已实现，实测以真实客户端为准。

## 1. 决策优先级与修改权限

1. Owner 当次明确授权；安全、隐私真实性、可访问性与平台原生可用性。
2. Zibblu 的产品行为约束：真实微信平台交互基线、业务状态、既有功能、品牌资产和已确认设计决定。
3. 当前代码库的语义 Token、组件契约与经 Owner 验收的视觉实现。
4. Always UI 相应模式的**设计、数值预设与审查方法**。与上面更高优先级冲突时，记录具体原因与必要例外。

**只改获授权的页面或模块**。从截图推断的设计差异需要验证；不要凭 Skill 偏好擅自替换现有页面、修改安全协议或回滚已验收的组件。其他模块的缺陷另记 Issue。

## 2. Always UI · 设计与验收流程

Always UI 已内置于 [`.agents/skills/always-ui/`](../.agents/skills/always-ui/SKILL.md)；各电脑和 Agent 优先使用仓库版本，无需依赖个人全局安装。固定上游提交与许可证见 [Skills](SKILLS.md)；不得只凭 Prompt 或记忆声称已读取引用。

| 模式 | 用途 | 允许变更 |
| --- | --- | --- |
| `$always-ui creative` | Owner 明确允许探索与当前风格明显不同的方向 | 可调整授权范围内的视觉方向，但仍保留指定品牌与功能/安全约束 |
| `$always-ui design` | 新界面、工作流、结构及信息层级整改 | 基于真实任务与平台重新组织授权区域，默认保留既有风格 |
| `$always-ui improve` | 既有界面的局部优化 | 保留导航、布局基线与视觉识别，只作最小高价值修改 |
| `$always-ui check` | 独立审查 | **只报告**有证据的问题与最小修复建议，不得自行改代码 |

- **Reference-first 强制执行**：设计/审查前先读当前 Skill 的规定文档。当前版本中，`creative`/`design` 必读 `design-intensity.md`、`design-archetypes.md`、`value-presets.md`、`visual-discipline.md`；`improve` 必读 `design-intensity.md`、`check-catalog.md`、`value-presets.md`、`visual-discipline.md`；`check` 必读 `check-catalog.md`、`visual-discipline.md`、`value-presets.md`。以仓库内固定 `SKILL.md` 为准；上游更新需另行审查并同步。
- 处理焦点、展开/折叠、文件名或宿主窗口拖拽时，还须按 Skill 要求阅读 `implementation-notes.md`。未能读取时报告缺口，不伪称完整使用 Skill。
- **数值选择顺序**：先检查 Zibblu 当前 Token 与平台度量 → 缺失时从 Always UI `value-presets.md` 分类表挑选固定值 → 仅因用户指定、内容尺寸、原生平台或无障碍等必要情况使用说明理由的例外。不得随意创造填充、字号、圆角、阴影、动效或断点值；**不得用预设反过来批判一致的既有 Token**。
- 应用 Always UI 的四项视觉纪律：颜色按品牌/语义分工、局部按钮层级、装饰须有理由、卡片/容器须有独立职责。这是按证据判断的原则，**不是固定色数或全局禁用渐变、卡片、玻璃**。
- `design`/其他设计模式实施后，按需要单独进行 `check` 审查；基于实际运行画面、代码和平台尺寸区分 **Defect / 高置信度设计问题 / 可选审美微调**。不把审美喜好冒充 bug。

## 3. Zibblu 品牌与跨端不变量

- **品牌**：Zibblu 原创标志、图标与 Lavender（薰衣草）主色。既有浅色普通 UI 与独立深色私密模式均须保留，除非 Owner 针对某部分明确授权重新设计。具体色值与视觉 Token 以当前项目实现和经批准的变更为准，旧版候选 HEX 不是强制固定值。
- **字体/控件**：各端系统字体、清晰的焦点、合理的触控区域及对比度；现有线性图标、选中态、小圆角与轻表面构成默认视觉基线。新设计仍由 Always UI 根据任务做取舍；不能用所谓“高级感”引入无用光效、冗余框架或假按钮。
- **按钮反馈**：鼠标使用默认、悬停和按下状态。键盘焦点使用中性色定位提示，高对比模式使用系统提示色。可用菜单项沿用当前主题的悬停色，相邻行的鼠标命中区连续，禁用项不响应操作。
- **所有带有效提示文案的文本输入控件**沿用已实现的 `FloatingField`：空且失焦提示在框内，聚焦或非空时标签上浮并与顶部边框融合。保留中文输入法、自动填充、真实 label、验证与原生键盘行为。
- **Windows 工作区**使用一套双层外壳。侧栏与顶栏共用 75% 不透明的磨砂背景且无阴影；聊天、通讯录、文件与设置共用内缩的小圆角前景内容容器，仅该内容容器外缘带低对比度、柔和羽化的悬浮阴影。聊天、通讯录和文件页的工作区搜索共用尺寸、左右内距、文本基线与放大镜锚点。
- **Windows 细节**沿用 1px 输入边框，聚焦时变色并显示柔和阴影。点击输入框外（含标题栏）即释放文本焦点并恢复正常边框。普通分界线为两端等距渐隐的 1px 细线，会话行的线从头像纵轴延伸至行尾内边距。滚动渐隐仅出现在有裁切的一侧，保留键盘与触控操作；可选正文使用中性灰色高亮。
- **Windows 非编辑 UI 文字不产生网页式误选中**；消息正文、代码及真实可编辑/可复制内容仍可选择复制。不得为隐藏浏览器感而取消系统安全权限。
- **不同平台按各自微信的实际使用习惯**：Windows 以 Windows 微信、iPhone 以 iOS 微信、iPad 以 iPad 微信的常规交互为基准；以 Zibblu 品牌与真实已实现能力呈现，**不逐像素复刻、也不复制微信素材**。此平台行为基线优先于 Always UI 的泛用布局原型。

## 4. 页面/交互契约

### 导航与资料

- **Windows**：主功能导航 / 列表 / 内容的三栏工作区；导航直达聊天、联系人和文件。当前页只在原图标内显示品牌紫填充与浅薰衣草内线，保留键盘焦点和原点击区。可点击的个人头像在指针旁显示只读资料卡，卡片受背景容器约束，点击外部或 Escape 关闭。手机端保留本人资料编辑和添加好友二维码。
- **Windows 通讯录**：左侧可搜索联系人列表，宽窗右侧显示选中资料，窄窗逐级进入并返回。切换工作区页面后，恢复选中联系人、资料、搜索和列表滚动位置。联系人按显示名称的拼音或首字母分组。点击联系人姓名或行内空白处进入详情并可管理私有备注，点击头像在原处打开只读快捷卡，两种操作共用整行选中背景。Zibblu 助手共用名称排序与备注入口，备注保存在当前服务器和账号的本机资料中。
- **Windows 聊天**：头像—名称—单行预览—时间—未读信息密度；从列表进入会话并聚焦输入。普通聊天输入区采用单行起步的浮起胶囊，附件在左、发送在右。两个按钮在单行时垂直居中，输入区向上扩展时保持该位置。六行后在内部滚动，仅有裁切的一侧显示渐隐。Enter 发送、Shift+Enter 换行，保留按会话的草稿。「+」提供附件和文件夹选择，剪贴板图片走快捷键或右键粘贴。顶栏「…」使用右侧**资料抽屉**，保持会话与返回上下文。
- **手机**：聊天 / 联系人 / 文件 / 我的四个底部入口，逐级导航、系统键盘与安全区域、长按/手势按对应平台实现。**平板**：宽度允许时列表与详情双栏，窄分屏能逐级返回。不得强加 Windows 弹窗或桌面悬停模式。
- **登录与设置**：Windows 可选账号及自定义服务器地址；可按现有能力连接企业自建在线服务。设置根据平台使用合适的分栏或层级，不增加未支持的按钮或字段。

### 消息、文件与媒体

- 消息菜单按桌面右键、移动长按；群人数使用真实同步成员。消息发送、未读、离线、撤回与回执的语义不能因视觉整改改变。**双方同意回执时**，仅当前单聊最后一条自己发送的消息适用状态：单勾表示对端已保存，双勾表示对方已查看；群聊及历史消息不冒充回执。
- Windows 将自己的发送状态固定在气泡左侧并垂直居中。排队或发送中显示空心圆环，失败可查看原因并重试。状态变化沿用同一位置，系统启用减少动画时圆环保持静止。
- Windows 聊天缩略图按原图纵横比缩放，靠头像的一边沿用文字气泡的间距。已有缩略图和正在上传的图片用本地尺寸预留位置。
- **文件页仅列需要下载且不能在聊天内直接预览的普通附件**；图片/视频在聊天与会话媒体历史中展示。聊天文件卡片承载名称、大小、真实传输/暂停/失败/恢复状态；保留完整性检验、断点续传及访问权限，不得借外观变更修改存储/授权语义。
- **Windows 文件中心**用单一列表展示共享文件和传输状态。每行首行是文件名，次行依次显示发送者头像、昵称、十进制大小和本地时间。文件中心与聊天共用本地日期格式：今天显示 `HH:mm`，昨天显示「昨天」，前天显示「前天」，更早但属于当前自然周（周一零点起）显示「星期一」至「星期日」，其余当年显示 `M月D日`，跨年显示 `YYYY年M月D日`。文件名可聚焦查看全名，通常只省略主体末尾。搜索、类型 Selector 与固定文字的「时间排序」位于列表顶部，搜索框只在可用空间不足时收缩。主操作贴齐列表右侧内容边界并保持同一位置，错误指示位于主操作左侧并垂直居中。

### 隐私、AI 与状态真实性

- **M1 普通在线聊天**经过所选在线服务器；普通消息不是端到端加密，自托管服务器可在投递阶段读取内容，界面不得暗示服务器不可见。长期历史与缓存遵守按服务、账号和设备隔离的本机数据契约。
- **M2 私密聊天**只在双方同意、身份校验后建立加密 LAN 直连；失败时无公网/云端回退，不持久化应用内私密正文，不把私密内容送至云 AI。深色仅是视觉区别，连接/认证/失败状态必须文字和图标可辨。
- **M3 AI** 由本次 `@名称` 或 Windows 内置 Zibblu 助手中的主动提问触发。Windows 安装器和应用内版本化条款披露默认范围及第三方外发；普通聊天 `@名称` 的跨会话检索使用任务内授权卡片，内置助手在接受涵盖其范围的当前条款版本后直接执行单次主动提问且不重复弹卡。权限只读，仅本次有效，M2 私密会话始终隔离。
- 错误、权限、隐私、危险操作、失败重试必须明确表达。减少解释性文字不能成为隐藏关键风险的理由。

## 5. UI PR 真实验收

1. 写明本次设计强度（`creative/design/improve`）、所读 Always UI reference、复用的项目 Token 与必要数值例外；把产品约束和泛用视觉建议分开。
2. 只报告**实际执行**的编译/测试与 Windows Tauri 客户端操作；UI 前后比较附实际窗口截图/录屏。iPhone/iPad 没有真机或真实平台环境时标记 `BLOCKED`，不能用浏览器或 CI 冒充通过。
3. 使用 `$always-ui check` 审查时保留证据、影响与最小修复建议；对不影响功能的审美偏好注明可选。回归检查依照当前 Issue，避免借审查扩张改动范围。
4. PR 由 Owner 验收后决定合并。**本文件不授权自动合并、部署、发布或关闭父任务**。
